# 审查一个候选版本

先确定比较基线、任务 ID 和原验收条件，再沿变更的调用链检查。只读审查不顺手改代码；不打开真实设备连接验证猜想。

- **接口与质量：** 从旧入口和新入口各走一遍；检查事件归属、关闭后的迟到消息、错误是否回到正确页面。用 `docs/interfaces/` 对照实际 Rust 签名，标出调用方无法兑现的保证。
- **依赖与资源：** 新依赖替代了什么？沿所有者找到连接、缓冲区、队列和子进程的上限与释放点。只有测量才能支撑资源改善，给结论附上场景、单位和平台。
- **安全：** 连接相关改动看 Host Key 与凭证流向；文件改动看选定目录、符号链接、覆盖确认和取消后的目标文件。用 `docs/testing/ACCEPTANCE.md` 的隔离样例核对。
- **输出：** 先列会改变合并或交付决定的问题，每条给出路径/符号、触发条件、实际后果和修正方向。没有发现就直说；把缺少的实测证据与已证实的缺陷分开。
