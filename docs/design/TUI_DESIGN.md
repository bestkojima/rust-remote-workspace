# 五页工作台与终端焦点

打开后落在 **Devices**：有设备就直接选中连接；空列表提供 N 添加入口。工作台顶行显示普通 SSH 会话数和隧道状态，第二行是带快捷键的导航。默认黑底终端用青色突出当前页；窄屏仅当前选项保留全名，让按键仍然看得见。

| 工作台按键 | 实际操作 |
|---|---|
| F1 Terminal | 恢复最近停放的终端；没有终端时 Enter 去选设备 |
| F2 Files | 选择设备，Enter 打开原有双栏 SFTP。q 离开文件浏览；弹层、搜索和复制模式保留自己的取消键 |
| F3 Sync | 管理目录对、编辑排除规则、查看预览并确认本次复制。在 Files 按 F7 可带入当前两侧目录。[同步操作](SYNC_USE.md) |
| F4 Devices | Enter 新建 SSH 会话，N 添加设备，/ 搜索；i 保留原文件入口 |
| F5 Settings | E 编辑工作台默认值，T 管理 VPS 隧道，P 管理 SSH 端口转发 |

在工作台顶层按 q 退出程序并结束工作台会话。在远端 shell、传输、表单或编辑器里，保留该模式的输入处理；F1–F5 不是全局拦截键。

### 添加使用加密私钥的设备

**F4 → N** 新增，或选中设备按 **E** 编辑。在 **Private Key Path** 填本机私钥路径，按 **Shift+Tab** 回到 **Key Passphrase**，输入解锁这把私钥的口令；未加密的私钥留空。**Ctrl+S** 可先保存新设备，不会发起握手。编辑时改选另一把私钥，要重新填写相应口令；要清除原口令，在口令栏按 **Ctrl+Del**。没有指定私钥时，该位置显示 **Password**，只用于 SSH 密码登录。

### 改新设备端口、终端历史或诊断日志

**F5 → E** 打开默认设置。Tab 换字段，Ctrl+A 替换整项，Enter 保存，Esc 放弃。新建设备时留空端口即采用这里的值；已有设备的端口不变。历史行数（1–5000）用于之后打开的终端，不清空当前屏幕。rclone 路径可以填含空格的完整路径，留空则从 PATH 查找。

“Log on next launch” 用左右键或空格选 off / info / debug，重启生效。命令行 `--log` 仍可单次启用日志（默认 info），`--log-level` 可指定级别；已启用日志时 `RUST_LOG` 优先。日志写入启动目录的 `termirs.log`，按 4 MiB 轮换，保留一份备份。

## 首次连接核对哪一串

看到 **Verify SSH host key**，先看地址和端口，再核对整串 `SHA256:…`。例如，目标是使用默认 OpenSSH Server 配置的 Windows 设备、弹窗算法为 `ssh-ed25519`：在**目标设备自己的 PowerShell** 中读取服务端公钥指纹：

```powershell
ssh-keygen -lf "$env:ProgramData\ssh\ssh_host_ed25519_key.pub" -E sha256
```

如果服务端使用了自定义 HostKey 路径，改用对应的 `.pub` 文件。没有设备控制台时，请管理员通过已有可信渠道提供指纹。用户登录用的 `id_ed25519.pub` 是另一把钥匙。[Windows OpenSSH 的主机密钥位置](https://learn.microsoft.com/en-us/windows-server/administration/openssh/openssh_keymanagement#host-key-generation)

- **相同**：按小写 **y**。工作台先保存服务器公钥，再用它验证下一次握手。设备列表或 Files 的连接继续进行；在换源或端口转发页面，则回到原操作，由你决定何时开始。
- **不确定或不符**：按 **n / Esc** 返回。Enter 不会同意；窗口太小看不全指纹时，放大后才能确认。
- **已知设备换钥**：红色 **Host key changed** 窗口列出 Saved 和 Received。连接停在用户认证之前，不能按 y 覆盖。先确认地址是否正确，再找管理员核实是否确实更换了服务器密钥。

升级沿用旧设备配置时，已有的服务器公钥仍用于比对，不会因升级弹出首次确认。对于过去由旧版自动记住的公钥，可从可信渠道补核对；不要为了看到弹窗而清空已有记录。

**使用旧版保存的登录密码？** 在原来的 Windows 账号中打开设备，按 **E → Enter** 保存。工作台会将旧密码和私钥口令换成由当前用户 [Windows DPAPI](https://learn.microsoft.com/en-us/windows/win32/api/dpapi/nf-dpapi-cryptprotectdata) 保护的格式；已保存的服务器公钥保持不变。仅打开配置不会改写凭证。新格式需要新版工作台和相应的用户凭证，不能把设备表当作跨账号搬运密码的办法。

## 用同一台设备打开三个 shell

在 Devices 选设备 → Enter → **F12** 把终端留在后台并返回 Devices。不用重新选设备，再按 Enter 新开一个。重复一次就有三个 Tab。**F6** 换到下一个，**F8** 只关当前会话。标签编号和高亮区分同名设备；实际事件按实例 ID 路由。

Files 内临时打开的 shell 借用当前浏览器连接，不加入普通标签。终端在前台只占用一行标题，把剩余行留给远端 PTY；resize 传递的是内容区尺寸。

## 经 VPS 打开开发机终端

先让管理员在 VPS 上把 rathole 服务端口绑定到回环，在开发机按[客户端说明](TUNNEL_AGENT.md)运行代理。家庭端只需要两条 SSH 配置，不需要复制隧道 token。

1. **F4 → N** 新建 VPS 和开发机两条 SSH 配置。VPS 填网关地址和 SSH 端口；开发机填 `127.0.0.1`、一个空闲的本地端口以及开发机自己的登录用户和密钥。**Ctrl+S** 只保存配置，不连接、不信任公钥。
2. **F5 → T → N** 新建路由。用左右键选两条配置，Tab 切字段，填 **VPS 上 rathole 对应服务的回环端口**，按 Enter 保存。
3. 选中路由，**Enter** 启动。首次核对 **VPS** 指纹；保存后关闭提示，再按 Enter。看到 **Forward ready**，说明网关已验证、本地端口已监听。
4. 按 **o** 打开开发机终端。此时核对的是**开发机**指纹；设备配置中的本地地址只是入口。从 Devices 或 Files 选该设备也走这条路由。

链路中断后，工作台按退避间隔重连 VPS；原来的 SSH shell 断开后须手动重新打开。密钥变更和用户认证失败会停止重试。**x** 停止所选路由并关闭它的转发连接，其他路由和直连设备不受影响。
