# SSH 首次信任与换钥：Windows 本机验收

在仓库根目录构建工作台，然后从真实控制台启动验收：

```powershell
cargo build --locked --bin rust-remote
uv run tools/smoke_host_key.py target/debug/rust-remote.exe
```

脚本创建一次性设备、客户端密钥和空 pin 的 TOML 配置。SSH/SFTP 服务只监听 `127.0.0.1`，每次运行生成两把不同的 Ed25519 主机密钥。用 AsyncSSH 计算服务端指纹，对照应用实际显示的字符；用服务端 `begin_auth` 统计最早的用户认证请求（包括 SSH 的 `none` 请求）。换钥时保留同一 IP、端口、设备 ID 和客户端配置。

| 操作 | 通过条件 |
|---|---|
| 在 Files 首次连接，停留 11 秒 | 地址和完整 SHA‑256 指纹正确，窗口仍可核对，没有发起用户认证或改写配置 |
| 按 Enter，再按 n；从 Devices 再次连接并按 Esc | 两次均未保存指纹，服务端的认证计数保持 0 |
| 临时用 Windows 文件共享锁禁止替换配置，按 y | 明确报错，未开始认证，原配置保持不变；解除锁后在同一进程再连仍须核对 |
| 按 y 确认后重启客户端 | 配置里的 OpenSSH 公钥等于已核对的服务端公钥；重启后可直接登录并收发回显 |
| 空配置下按 N，新建设备，Esc 拒绝后用原表单再连接并同意 | 拒绝后表单内容保留，配置文件还没创建；同意后只新增一条带正确公钥的设备，可登录 |
| Files 保持右侧 A 在线，从左侧切换到首次连接的 B | 取消后恢复原两栏，B 未认证、未写 pin；确认后按提示重选 B，左侧列出 B 独有文件，右侧继续显示 A 的文件 |
| 在原地址更换主机密钥，再连接并按 y | 界面显示已存/收到的两个指纹，换钥被拦截；旧 pin 保留，服务端无任何用户认证请求 |

验收单一入口时可加 `--files-only` 或 `--forwards-only`。Files 单测场景会为 A 预置本地测试公钥，B 从未信任状态开始。

## 本机验证记录

同一配置也可用两个工作台同时打开。运行 `uv run tools/smoke_shared_config.py target/debug/rust-remote.exe`：一端已保存新记录后，另一端在旧弹窗按 y 会重新核对磁盘，换钥时仍显示两个指纹并阻止登录。无关设置若来自旧快照，保存会提示重开工作台，避免覆盖较新的设备记录。写锁文件只协调进程，不存放设备信息。

Windows 11 专业版 10.0.26200、x86_64 MSVC debug，Rust 1.97.1；服务端为 AsyncSSH 2.24.1。首次弹窗中实机读取到以下内容（每轮的临时指纹省略）：

```text
Verify SSH host key
SHA256:<本轮设备的完整指纹>
y  Trust and save     n / Esc  Cancel
```

原生按键测试观察到：Files 首次连接可以停留 11 秒核对，Enter 没有授信；n 和 Esc 均没有改写临时配置，服务端认证计数为 0。保存被文件共享锁拒绝时看到 Error，失败后在同一进程仍需重新确认。解除锁后按 y 保存了与该服务端一致的 OpenSSH 公钥。重启客户端后同钥免重复提示，服务端返回了新的输入回显。

从空配置按 N 新建时，首次拒绝回到仍保有输入内容的表单，磁盘上没有创建配置。再次提交并确认后只新增一条记录，能够登录。同一 IP:port 换钥时，窗口分别显示已存与收到的完整指纹，按 y 无效，未向换钥端发起用户认证，旧 pin 保留。

最终整合版（2026-11-19 22:51:37 构建）完整脚本退出码 **0**。Files 换源与转发确认曾在 Windows debug 客户端触发栈溢出，修复后在同一组原生操作中复验：保留右侧 A，从左侧选择 B，Esc 后仍停留在原浏览器；确认后按提示重选 B，可以读取 B 独有的文件。此时在 A 的远端目录新建标记，再切到右栏按 r 能看到新标记，证明 A 的连接仍能读取新数据。随后把 B 的测试公钥换到 A 原来的地址，A 依然被拦截；一台设备获准的公钥不会替另一台设备取得信任。

在 Settings 按 P 进入 SSH 转发列表后，选临时回环转发并按 Enter，原页显示目标指纹。Esc 返回原规则，未发送认证请求、配置未改。再次进入并按 y 只保存 pin：服务端认证计数不变，测试端口仍可被独立套接字绑定。关闭提示再按 Enter，客户端才开始用户认证，规则显示 started；再按 Enter 显示 stopped。完整脚本与工作台均正常退出。
