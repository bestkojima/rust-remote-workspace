# 设备登录凭证：保存、迁移与恢复

**Windows 用户：** 在原 Windows 账号打开设备表，选中设备按 **E → Enter**，即可把该表内的旧密码和 SSH 私钥口令一并迁移。新建时 **Ctrl+S** 可以先保存设备、暂不登录；首次 SSH 连接仍须另行核对服务器指纹。私钥文件本身不会被复制进设备表。

录入加密私钥时先填 **Private Key Path**，按 **Shift+Tab** 输入 **Key Passphrase**。工作台用它在本机解锁私钥，两个认证栏分别保存输入；清除私钥路径不会把解锁口令当作 SSH 登录密码发送。

| 场景 | 结果 |
|---|---|
| 仅打开旧表、使用已固定的设备登录、更新最近连接时间或同步日志 | 旧格式可以读取；自动更新的元数据沿用原密文，不触发迁移。 |
| 明确保存设备表（包括批准保存 Host Key、编辑设备或工作台设置） | 在同一次原子替换中将表内仍存的旧凭证全部迁移。编辑或删除写入失败，不更改已显示的设备或规则；其他客户端已更新同一表时，须重开后再改。 |
| 重启后读取新格式 | 使用下列平台保护；如果不能解密，拒绝打开，不回退到空密码或覆盖设备表。错误和 Debug 不回显凭证明文或密文。 |
| 无密码、无私钥口令 | 不需要凭证存储；指定私钥路径或使用现有的自动选钥方式即可。 |

## 凭证跟哪个账号走

- **Windows：** TOML 中的 `dpapi-v1:` 标记表示 [Windows DPAPI](https://learn.microsoft.com/en-us/windows/win32/api/dpapi/nf-dpapi-cryptprotectdata) 当前用户范围。系统保护和解锁，不弹出交互窗口。用原 Windows 用户环境和对应的 DPAPI 恢复材料；单独复制设备 TOML 到另一台机器或账号无法保证解密。
- **Unix：** `unix-key-v1:` 使用随机 256 位用户主密钥和每次独立的随机 nonce，以 AES-256-GCM 保护密码。Linux 的密钥在 `$XDG_DATA_HOME/rust-remote/credentials/master.key`（未设置时在 `~/.local/share/rust-remote/credentials/`）。凭证目录限当前用户（0700）；主密钥文件限当前用户读取（通常 0600）。后台服务、图形钥匙串、主机名和用户名均不参与生成密钥。目录路径须由当前用户或 root 控制，不使用符号链接。
- **恢复：** Unix 应将原 `master.key` 作为秘密单独备份；手工迁移时恢复原密钥、属主和权限。已有加密设备表遇到缺失或更换的密钥会停止，恢复原密钥后重试。新工作台只读旧版 TermiRs 的未标记凭证；旧版程序无法读取新格式。换机前优先在原环境迁移或在新设备表手动重新录入。不要把密码、主密钥、私钥或密文贴进工单。

能在原用户权限下运行代码的程序仍可能取用凭证。服务器身份由 Host Key 固定；凭证存储不会替代首次核对。隧道 token 有[独立的受限文件](../design/TUNNEL_AGENT.md)。

## 本地验收

```powershell
cargo test --locked --lib config::
cargo build --locked --bin rust-remote
uv run --script tools/smoke_credential_login.py target/debug/rust-remote.exe
```

2026-11-20 Windows x64 / MSVC：配置组 19 项通过，1 项访问真实 SSH 配置的测试按设计跳过。用临时设备表覆盖了密码/私钥口令、空值/Unicode/首尾空格、密文篡改、旧格式的读取与整表迁移、自动写不回退、写锁冲突后的设备及转发规则回滚、规则编辑重启可见。上面的原生 TUI 测试通过独立的 Windows DPAPI 接口检查封套，再用回环 SSH 验证保存、编辑和重启登录；只用临时随机口令。测试不需要读取已有用户配置、私钥或密码库。

加密私钥的表单回归使用原按键和粘贴处理器、新建的临时设备表。填写路径后返回口令栏，离线保存并重新读取，带首尾空格的口令完整。编辑时清除、重新填写、换钥均按预期；撤销不能找回上一把钥匙的口令，清空私钥路径也不会泄露给密码认证。该轮覆盖表单与持久化，未另做使用加密私钥的真实 SSH 登录验收。

Linux 在本机没有运行环境。对应的隔离测试随源码提供（同一 `cargo test --locked --lib config::`）：首次并发创建用户钥匙、拒绝开放权限或错误密钥、打开配置后移走或替换密钥时拒写，恢复后可继续保存。Linux 单元测试使用独立临时密钥目录。
