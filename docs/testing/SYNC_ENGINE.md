# Sync：预览、逐项确认和实际传输

在项目根目录运行，最后一个参数是[官方 rclone 1.72.1](https://downloads.rclone.org/v1.72.1/) 的本机可执行文件。测试使用 AsyncSSH 2.24.1、临时 Ed25519 密钥、临时目录和回环 SFTP；无需设置真实设备。

```powershell
uv run tools/smoke_sync_engine.py C:\tools\rclone-v1.72.1\rclone.exe
cargo test --locked --lib windows_sync_staging_and_published_file_keep_private_permissions
```

## 先确认远端目录的实际边界

初次连接先核对 SSH 指纹。Sync 在读取目录前另外核对设备、地址、端口、账号、已保存的主机公钥和远端根目录；任一变化都会使旧授权失效。普通 SFTP 路径操作无法阻止另一进程在检查后将父目录改名、换成链接。选择符合现场条件的一项：

- **已设隔离根。** 管理员确认此 SFTP 账号的可见根 `/` 就是本次授权的目录，其他写者不能接管本任务的私有暂存目录。仅当 Profile 的远端根为 `/` 才能保存这一授权。
- **本次独占。** 从扫描到确认、执行结束，操作者能保证没有其他进程能替换远端目录树、它的祖先或任务暂存目录。只对一次预览有效；取消、重试或重启后必须重新确认。

普通共享目录不满足这两项时，请保留未授权状态。引擎在读取远端目录或启动 rclone 前停止。远端上传暂存目录创建时请求模式 0700；SFTP 服务器需要落实相应的私有权限。

## 一次预览授权哪些操作

预览读取两侧内容、应用排除规则，再对候选清单实际运行 [`rclone copy --dry-run`](https://rclone.org/commands/rclone_copy/)。默认跳过同名差异。源和目的是否仍是预览中的版本，以流式读取的内容指纹判断；大小、时间相同不能证明内容相同。执行消耗这次预览。执行中的新增源文件不会进入已确认清单。

执行时，每次只暂存一份文件，通过 [rclone SFTP](https://rclone.org/sftp/) 和只包含当前获准文件的清单复制。Rust SFTP 预检和 rclone 分别检查设备公钥；rclone 的临时 `known_hosts` 来自已保存的公钥。停在首次信任时没有复制；对端密钥变化会让连接失败。Sync 使用设备指定的密钥或密码；自动选钥只使用已在该设备登录成功的标准密钥路径。无认证方式的配置不会自动尝试本机 SSH agent。[rclone 1.72.1 的 SFTP 认证选择](https://github.com/rclone/rclone/blob/v1.72.1/backend/sftp/sftp.go#L915-L925)。工作台不启用远端 shell 或远端校验和命令。

| 目标 | 遇到同名差异时 |
|---|---|
| 本地 Windows 普通文件 | 可逐项批准。取得禁止并发写入的文件句柄后再比对版本；有写者、版本变化或路径变为链接时保留原件。候选在创建时继承原文件的访问控制表。 |
| SFTP v3 或本地非 Windows 文件 | 保留目标，显示冲突。通用 SFTP 没有比较版本并替换的操作，普通 Unix 文件锁也无法约束未参与锁协议的写者。 |

新增目标采用不可覆盖的发布操作。远端优先以 SFTP hardlink 发布已核对的临时文件；没有该扩展的服务端用排他创建。后一条路径若在写入时掉线，会报告可能残留的**新文件**。工作台不传播删除，目标独有文件不参与写入。取消会终止并回收 rclone；已发布的文件保留。断线时无法清理远端临时目录，会给出本次目录名；不要据此批量清理其他目录。

## Windows 本机通过的场景（2026-11-20）

- 首次上传包含中文和空格的子目录；取消预览后，远端只有原有哨兵。确认后逐字节核对，目标独有文件仍在。
- 二次预览无变化。预览之后新增的源文件未被复制；预览之后出现或发生同长度修改的目标得到保留。Windows 本地明确批准的同名差异可覆盖。
- `build` 排除规则生效；本地目录 junction 作为源时被跳过，作为目标路径分量时也未向外部目录写入。
- 无远端目录授权时，连指定的不可运行 rclone 路径都不会触发；账号、公钥、地址、端口、设备 ID 或根目录变化会使旧授权失效，一次性授权不能重用或通过序列化续期。
- rclone 使用错误主机公钥单独尝试复制时，服务端没有收到目标文件。Rust 连接缺少 pin 会返回首次指纹确认。
- 实际上传 4 MiB 文件时暂缓 SFTP 服务端，取消任务：未发布该目标；连接仍可用，临时目录被移除。
- 在 Windows 上读取真实安全描述符：初始暂存目录禁用继承，只授权所有者和 SYSTEM；覆盖原文件后有效 DACL 与原件一致。持有写句柄时，批准覆盖仍保留原件。

同步仅在操作时扫描。首次预览会读取文件内容；复制期间约每 500 ms 接收 rclone 的字节进度。任务未使用 `sync`、`bisync`、常驻扫描或自动覆盖。

## 断线后从哪里重传

**当前工作台按文件恢复。** Windows 本机、rclone 1.72.1、AsyncSSH 2.24.1，分别测上传和下载。每次让一个 28 字节的小文件先发布，再传 4 MiB 大文件。在服务端记录 SFTP 偏移与长度，成功接收或提供 2,097,152 字节后断开连接。

| 方向 | 断线前的大文件数据 | 重新预览、确认后：大文件首偏移 / 实际传输量 | 小文件重传量 |
|---|---:|---:|---:|
| 上传 | 2,097,152 字节 | 0 / 4,194,304 字节 | 0 字节 |
| 下载 | 2,097,152 字节 | 0 / 4,194,304 字节 | 0 字节 |

断线时，目标端只有完整的小文件，大文件尚未发布。再次预览跳过这个内容未变的小文件；重新确认后，大文件进入新的暂存区，最终内容逐字节一致。表中统计的是 rclone 搬运文件内容的 SFTP 读写，排除了预览和版本核对的读取。用本页开头的命令可复跑，两行 `upload:` / `download:` 分别输出首次和重试的连续字节范围。
