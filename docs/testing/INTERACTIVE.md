# Windows：用三个真实 SSH 会话验收工作台

构建候选可执行文件后，在项目根目录运行：

```powershell
uv run tools/smoke_workspace.py target/debug/rust-remote.exe
```

脚本为每次运行生成新的主机密钥和客户端密钥，预置服务端公钥，启动仅监听 `127.0.0.1` 的临时 SSH/SFTP 服务。TUI 通过 `--config` 读取一次性设备配置。终端只回显带会话编号的输入，SFTP 以临时目录为根；测试不需要安装或配置系统 sshd。

## 什么算通过

1. 连同一设备三次。每次经独立 SSH PTY 收到不同的服务端标记，前台的输入只由对应的连接回显。
2. 切到 C 时，由服务端向后台 B 写入一行。F6 切回 B 后能看到它；A、C 的缓冲中均找不到 B 的内容。
3. C 保持前台，在服务端断开 B 的传输。C 和 A 都继续响应新输入；回设备页后显示两条连接。F1 恢复 A，再按 F8 关闭它，C 仍在。
4. 进入 Files，选择设备。两栏分别显示本地、本次 SFTP 服务端的标记文件。用 `c → Tab → v` 上传本地文件；进度窗显示完成，服务端文件与原文逐字节相同。回工作台并正常退出。

脚本驱动真实 Windows 控制台按键并读取可见字符；仅当以上断言和退出码均通过时，脚本返回 0。

## 2026-11-19 实测：通过

平台：Windows 11 专业版 10.0.26200，AMD Ryzen 7 9700X（16 逻辑处理器）。候选为本项目 `rust-remote 0.3.4`，Rust 1.97.1，Windows MSVC debug 构建。由 Python 3.12 / AsyncSSH 2.24.1 运行测试服务。

- A、B、C 的 `alpha`、`bravo`、`charlie` 均回到所属屏幕；B 在后台接收的文本只出现在 B。服务端强制断开 B 后，C、A 分别响应新的 `survives` 和 `alive` 输入，设备页计数为 2。手动关闭 A 后返回 C。
- `LOCAL.txt` 出现在第 15 列，`REMOTE.txt` 出现在第 75 列。手动上传 1 MiB 已知字节序列，目标文件逐字节相等。应用与验收脚本都以 0 正常退出。

| 同一轮运行的观测 | 值 |
|---|---:|
| 创建进程到设备列表可见（50 ms 轮询） | 132 ms |
| 设备页空闲 Working Set | 14.5 MiB |
| 空闲 CPU（进程用户态 + 内核态，100% = 一个逻辑核，5.02 s） | 0.62% |
| 1 / 3 个 SSH 终端完成首次回显后的 Working Set | 22.9 / 23.5 MiB |
| 保留 1 个 SSH 终端，从打开 Files 到上传完成的最高观测 Working Set | 26.9 MiB |

内存只计工作台进程。Files 段以 20 ms 为目标间隔取得 109 个样本；26.9 MiB 是该段采样最大值。上述数据是一轮本地 debug 观测，不代表发布构建或大目录扫描性能。Linux 客户端、真实 VPS 链路与 rclone 同步尚未在此测试。

## Phase 2 收尾：颜色、窗口与手动重连

在同一台 Windows 11 机器上用 Host Key 改造后的 debug 客户端运行上述脚本。三个标签运行时，服务端向前台 C 写入 ANSI 亮红色和 reset 序列；读取实际控制台的对应字符，亮红 / 普通文字的前景色值分别为 12 / 7。将真实控制台窗口从 120 × 30 缩小到 110 × 27，服务端 C 收到的 PTY 尺寸从 120 × 29 变为 110 × 26；恢复窗口后又回到 120 × 29（标题占一行）。

服务端断开后台 B 后，A 和 C 都返回了新的输入。使用同一设备配置手动重连，第四个 shell 可输入、可回显，没有 B 的旧记录。关闭第四个 shell，原 A、C 都保留。随后仍可打开 Files，上传 1 MiB 文件并逐字节比对通过。整轮脚本退出码 0。

最终整合版（2026-11-19 22:51:37）的公共按键分派修正后，完整重跑退出码 **0**。同一轮首屏 207 ms，空闲 14.6 MiB / 单核 0.00%（5.01 s 内未测到 CPU 时间增量），1 / 3 个终端分别为 23.1 / 23.6 MiB；保留一个终端并在 Files 上传期间，107 次采样的最高观测值为 27.5 MiB。本轮与独立的 Host Key 验收并行，仅记录工作台进程；其余采样口径同上。
