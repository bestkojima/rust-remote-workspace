# Files：在双栏间往返一个文件

按 **F2** 选 SSH 设备并回车。左栏起初是本地目录，右栏是远端；**Tab** 换栏。地址、大小、修改时间均来自各栏自己的文件系统。

| 在当前栏按 | 操作 |
|---|---|
| ← / → | 返回上级 / 进入选中的目录 |
| g | 输入目录地址，可用绝对路径，也可相对当前目录。输错仍留在原目录 |
| m / 大写 R | 输入新目录名 / 为选中条目输入新名称。重命名不会覆盖已有同名项 |
| d | 确认后删除选中的文件或空目录。Esc 取消；非空目录不会递归删除 |
| c → Tab → v | 选中一个或多个来源，换到目标栏粘贴。Esc 中止传输；等待结果后按 Enter 回到当前目录 |
| F7 | 将当前本地、远端两个目录带入 Sync 的新 Profile 表单 |

**取消的边界是单个文件。** 传完才发布最终文件名。取消时已完成的文件与已创建的目录保留，未完成的暂存文件会清理。如果远端中断使清理失败，错误中会列出需在重连后检查的暂存路径。覆盖优先使用服务器的 OpenSSH 原子重命名扩展；只有 SFTP v3 时，先在同目录保留旧文件，再发布新文件，恢复失败会列出备份路径。Windows 本地覆盖保留已有文件的 DACL；远端只能处理 SFTP 提供的权限属性。

## 跑真实键盘验收

```powershell
cargo build --locked --bin rust-remote
uv run tools/smoke_files.py target/debug/rust-remote.exe
cargo test --locked --lib filesystem::
```

2026-11-19，Windows 11 x64 / MSVC debug 的真实控制台，临时 AsyncSSH 2.24.1 服务仅监听本机，SFTP 根目录和凭证均为本轮临时数据。原生脚本退出码 **0**；文件系统专项 **4 项通过**。

- 空远端根能打开，按复制、删除、重命名和打开不会误操作。直接输入带盘符、空格的 Windows 目录与以 `/` 开头的远端路径；输入无效路径报错，原右栏目录仍可用。
- 新建并进入远端子目录，用左方向键返回。上传 660 字节的 `数据 sample.txt` 覆盖已有内容，改名为 `renamed 文件.txt`，下载至另一本地目录，逐字节一致。删除先取消检查原文件仍在，再确认删除；已下载的副本未变。
- 测试服务刻意挂起读取，在传输中按 Esc：旧目标内容不变，目录里没多出临时文件。释放读取后重试，1 MiB 完整到达。目标为仅允许测试账号访问、禁止继承的文件；覆盖后权限条目、顺序及禁止继承状态仍一致。
- 选中待上传文件后，夹具移除该来源再粘贴。错误在界面可见，远端原目标与目录内容保留；切回之前停放的 SSH 终端，仍能收到新输入的回显。
- 两台 SFTP 服务在 `/collision.txt` 放置不同内容。取消切换来源，选区仍在；真正换掉来源，按粘贴提示未选文件，目标不变。只切换目标栏则保留来源，粘贴的正是首台服务器的内容。两台服务器间另传一个含子目录的文件夹，并反向传 1 MiB，回读一致。

本测试覆盖 Windows 本地路径与 POSIX 格式的 SFTP 路径。服务进程运行在 Windows；Linux 主机上的实际运行证据由平台验收单列。

## 直接调用同一个传输接口

Windows 上运行 `cargo test --locked --lib headless_file_copy`，两项测试通过。临时 SFTP 服务上的中文及含空格文件可上传、下载、在两台设备间复制；收发字节数与回读内容一致。上传和下载都在收到首个进度事件后取消，原目标保留且未留下暂存文件；缺少源文件时，调用方收到错误。[Rust 调用示例](../interfaces/CORE_API.md#无-ui-的单文件传输)
