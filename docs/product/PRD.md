# 在一屏内操作获授权的远程开发机

用户打开 `rust-remote`，选中一台设备，开三个 shell：一个看日志，一个构建，一个改配置。切去 Files 拿回构建产物，再切回 Terminal 时，三个 shell 的输入、历史和进程仍各归各位。

以下是产品验收目标。要知道当前版本能做哪一步，见[实测状态](../agent/CURRENT_STATE.md)。

| 优先级 / 页面 | 用户能完成什么 |
|---|---|
| P0 · Devices / Settings | 保存多台设备的名称、VPS 地址/端口、SSH 用户/端口和密钥路径。手动连接或断开；区分隧道与 SSH 状态，超时和自动重连均可见。设置工具路径、日志、资源上限。首版手动配置。 |
| P1 · Terminal | 每个具名 Tab 拥有独立 SSH Session 与有界历史。支持 ANSI/VT100、输入输出、滚动、窗口缩放与独立关闭；一个断线，另两个可继续工作。 |
| P2 · Files | 本地在左、远程在右。键盘选择、上级、直接输入路径；显示大小和修改时间。支持建目录、重命名、上传、下载、删除确认；展示进度、取消和失败。分别处理 Windows 本地路径与远端路径。 |
| P3 · Sync | 保存多个目录对，手动选中一个 Profile，预览新增和覆盖，确认后才单向复制；显示结果、进度和错误。[冲突与范围规则](../design/SYNC_DESIGN.md) |
| P4 · 配对（后续） | 高熵限时一次性码，两端确认，服务端验证绑定并安全下发设备专属参数，显示在线状态。rathole Token 不作短码；引入控制服务前写 ADR，评估复杂度、安全与资源代价。 |

**一屏的职责。** 顶栏显示设备、SSH 与隧道各自的状态；中部保留 Terminal / Files / Sync / Devices / Settings 五个入口；底部显示当前焦点能用的快捷键、任务及错误。优先 Ratatui 原生 Widget 和键盘操作。断线后用户仍能切页、看错误、重连或换设备。

**部署边界。** 家庭端通过 VPS 的受控转发访问已授权的开发机；公司端主动连到 VPS。转发到开发机 SSH 的端口只监听 VPS 回环接口；家庭端经验证的 SSH 连接访问。设备密钥和隧道 Token 分别管理。连真实公司网络前须取得许可并遵守网络政策。

**交付边界。** 第一阶段只做 Rust CLI + Ratatui；GUI 将直接调用同一 Core。rathole 按隧道生命周期启动，rclone 按任务启动；无常驻文件扫描、数据库、浏览器内核或 HTTP 适配服务。自动同步和双向同步单独立项，先验证数据安全。
